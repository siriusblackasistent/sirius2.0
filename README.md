# Sirius 2.0

Домашній помічник на Python з українськими командами, Telegram-керуванням
і плагінами розумного будинку. Прямі команди запускають потрібний плагін,
а GPT-роутер допомагає розпізнавати запити звичайною мовою.

API, Telegram-бот і медіасервер запускаються однією командою в одній `.venv`.
Вебінтерфейс і голосовий демон — окремі сервіси, які цей репозиторій самостійно
не розгортає.

## Можливості

- Tuya/Sonoff: керування обладнанням, читання стану та фонове опитування.
- Midea: керування кондиціонером і читання температур.
- Окремі Telegram-меню та доступи для різних будинків і користувачів.
- GPT-роутер з короткою пам'яттю, діалоги, таймери та відкладені команди
  з підтвердженням виконання.
- HDRezka: пошук із кнопками вибору, відтворення через VLC/HDMI, пауза,
  якість, озвучки та перемикання серій.
- Hikvision: JPEG-знімок у дозволений Telegram-чат за командою `кам1`.
- Smart Life: QR-підключення облікового запису та список доступних приладів.

Проєкт розвивається на основі плагінів Irene Voice Assistant. Сценарії будинків
мають номери `0`, `30` і `70`; це області налаштувань та доступу. Для власного
встановлення потрібно вказати свої пристрої, облікові дані й Telegram-чати.
Це робочий проєкт у розвитку: універсальний майстер додавання обладнання
ще не завершений, а плагін будинку 70 поки є заготовкою.

## Вимоги

- Linux, Python **3.12+** із модулем `venv`.
- Доступ до локальної мережі для керування обладнанням.
- Для HDMI-відтворення: системний VLC (`cvlc`), запущена графічна сесія
  та підключений екран або проєктор.
- Для Telegram, GPT та хмарних інтеграцій потрібне інтернет-з'єднання
  й відповідні облікові записи.

## Встановлення

```bash
git clone https://github.com/siriusblackasistent/sirius2.0.git
cd sirius2.0
bash deploy/setup.sh
```

Скрипт створює `.venv`, встановлює `requirements.txt`, створює `data/`,
`status/` та копіює шаблон `core` у приватний `core.py`, якщо його ще немає.
Служби не встановлюються й не запускаються автоматично.

Типово скрипт використовує `python3.12`. Для іншої встановленої версії 3.12+:

```bash
SIRIUS_SETUP_PYTHON=python3.13 bash deploy/setup.sh
```

## Налаштування

Відредагуйте `core.py`:

1. `server.api_key` — власний випадковий секрет для зв'язку бота з API.
2. `telegram.bot_token`, `adminChats`, `adminUsers`, `guestChats` — дані бота
   та дозволені користувачі/чати. `telegram.example.json` показує форму меню
   без персональних ідентифікаторів; перенесіть потрібні поля в секцію `telegram`.
3. `gpt` — ключі для GPT-роутера й діалогу, якщо потрібні ці можливості.
4. `rezka`, `midea`, `weather`, `calendar` — лише потрібні вам інтеграції.
5. `services` — увімкніть потрібні компоненти:

```python
'services': {
    'assistant': True,
    'telegram': True,
    'media': True,
    'status': True,
},
```

`False` вимикає компонент. Порожній `media.python` означає використання спільної
`.venv`. Типові адреси: API `127.0.0.1:5003`, медіасервер `127.0.0.1:8766`,
керування VLC `127.0.0.1:4213`. Якщо порт зайнятий іншим помічником, задайте
інші значення в налаштуваннях.

У плагінах `plugin_light_control_hause0.py` і `plugin_light_control_hause30.py`
на початку функцій приладів залишені порожні `ip`, `device_id`, `local_key`.
Заповніть дані власного обладнання. Непотрібне фонове опитування можна вимкнути
через `services.status`. Порожній ключ не дає доступу до реального пристрою.
Не публікуйте заповнені ключі зі своїх плагінів: `.gitignore` не приховує
секретів усередині Python-коду.

`core.py`, `.venv`, локальні облікові дані, журнали та `data/` не входять до Git.
Секрети також можна передавати через змінні `SIRIUS_*`; вони мають пріоритет.

## Запуск

```bash
.venv/bin/python run_sirius.py
```

Після початкового налаштування достатньо цієї команди. Telegram очікує готовності
API. Якщо дочірній процес завершується, спільний запуск зупиняє решту компонентів.
`Ctrl+C` зупиняє групу, включно з її VLC-процесами.

Для автоматичного запуску є шаблон `deploy/systemd/sirius2.0.service`.
Перед встановленням задайте власні `User`, `Group`, `WorkingDirectory`, `ExecStart`.
У шаблоні шлях встановлення — `/opt/sirius2.0`. Не запускайте одночасно одну
спільну службу та окремі служби того самого API/бота.

## Команди та доступи

Приклади: `меню`, `статус`, `час`, `знайди назву фільму`, `таймер 5 хв`,
`через 5 хв вимкни все світло`, `кам1`, `smartlife`.
Доступність команди залежить від налаштованих плагінів та будинку користувача.

Сесії відокремлені за чатом і користувачем. Пам'ять GPT-роутера зберігає три
останні обміни до 60 секунд бездіяльності. Активний контекст GPT-діалогу
має окремий таймаут 3 секунди. Перезапуск очищає сесії й таймери в пам'яті.

## Hikvision

Скопіюйте `options/hikvision.example.json` у `options/hikvision.local.json`
і задайте URL, логін, пароль та ISAPI-канал камери (типово `101`).
У прикладі використано документаційну адресу — замініть її реальною.
Обмежте права файла: `chmod 600 options/hikvision.local.json`.

`кам1`, `камера1` та `камера 1` надсилають знімок у дозволений чат запиту.
Камера 1 може бути дозволена будинкам 0 і 30 через `allowed_homes`.
Чати будинків визначаються за `telegram.guestChats`; саме твердження в тексті
«будинок 30» доступу не надає. Знімки обробляються в пам'яті.
Для кнопки додайте `кам1` у `menuAdmin` і меню потрібного будинку.

## Smart Life

У будинку 0 напишіть `smartlife`, введіть код користувача Smart Life,
відскануйте QR в застосунку й натисніть «Перевірити підключення».
`smartlife список` повторно читає список, `smartlife підключити` створює новий QR.
На одному телефоні можна спробувати вибрати збережений QR зі сканера застосунку.

Використовується офіційний `tuya-device-sharing-sdk` і публічний клієнт
QR-авторизації інтеграції Home Assistant; власні `client_id`, `schema`
можна задати в секції `smartlife`. Пароль застосунку не запитується.
Фактичний QR-вхід залежить від доступності хмари та підтвердження користувача.

Авторизація та реєстр зберігаються приватно в `data/smartlife/`.
Код не передається GPT. Реєстр передбачає поля назви, опису, розташування
й призначення. Поки плагін читає список: він не вмикає прилади, не сканує LAN
і не переписує плагіни керування світлом.

## Структура

| Файл або папка | Призначення |
| --- | --- |
| `run_sirius.py` | Спільний запуск компонентів |
| `sirius_core.py` | Ядро, плагіни та сесії |
| `run_sirius_server.py` | HTTP API |
| `run_remote_telegrambot.py` | Telegram, меню та кнопки |
| `core` | Порожній шаблон приватних налаштувань |
| `plugins/` | Команди й інтеграції |
| `rezka_catalog.py` | Каталог фільмів |
| `rezka_media_server.py` | VLC/HDMI та медіакерування |
| `deploy/` | Встановлення й шаблони служб |
| `tests/` | Перевірки без реальних перемикань приладів |

`run_guest_web.py` — необов'язковий адаптер для вже наявного окремого вебдемона.
Вкажіть `SIRIUS_VOICE_DIR`; сам вебдемон, його авторизація та Whisper не включені.

## API та перевірки

`POST /message` приймає `text`, `chat_id`, `user_id`, `home`, `user_name`
із заголовком `X-Sirius-Key`. `GET /health` показує завантаження плагінів.
`GET /notifications` повертає готові нагадування. Сумісні вебмаршрути доступні
лише безпосередньо з loopback, основний API перевіряє ключ.

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
PYTHONPATH=tests .venv/bin/python -m unittest discover -s tests
```

Для HDRezka закріплено `soupsieve==2.8.4`: версія 3.x несумісна з CSS-селекторами
в HDRezka 5.2.0. Пошук не запускає відео до вибору конкретного результату.
Реальне обладнання, Telegram-доставку, QR-вхід і зображення на HDMI потрібно
перевіряти окремо після заповнення власних налаштувань.
